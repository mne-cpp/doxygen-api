43/*
44 * Conventions with FIFF_ C macros (mjk 14.01.2000).
45 *===========================================================================
46 * In order to get some order into the FIFF_ macros,
47 * following macro types are proposed:
48 *
49 * FIFF_ Fiff tag object identification label.
50 * FIFFB_ Fiff block tag value (block type indentification label).
51 * FIFFV_ Enumerated value of data having definite meaning in some context.
52 * Would be nice if the context is also present like:
53 * FIFFV_HPI_ACCEPT_PROGRAM and FIFFV_HPI_ACCEPT_USER.
54 * FIFFC_ Independent constant value like FIFFC_MATRIX_MAX_DIM used in
55 * code (having meaning in 'programming context' but not as data).
56 * FIFFT_ Fiff type descriptor.
57 * FIFFTS_ Fiff type decriptor (FIFFT_) structure definition (see below).
58 *
59 *
60 *
61 * Conventions on type codes: (mjk 14.01.2000)
62 *===========================================================================
63 * Fiff types are saved using 32 bit numeric indentifiers.
64 * The fiff type codes are structured so that they contain two main parts:
65 * the 'fundamental structure' and 'type details'. The fundamental structure
66 * is coded in the MSB of the 4 byte code. Depending on this code the
67 * interpretation of 'type details' may vary.
68 *
69 * Current Fundamental structures:
70 *----------------------------------------------------------------------
71 * Only the MSB is significant. See FIFFTS_FS_MASK
72 *
73 * FIFFFS_SCALAR 0x00000000 Scalar type / basic fixed size FIFF record.
74 * FIFFFS_RECORD 0x10000000 <reserved>
75 * FIFFFS_...... 0x20000000 <reserved>
76 * FIFFFS_...... 0x30000000 <reserved>
77 * FIFFFS_MATRIX 0x40000000 Multidimensional matrix.
78 *
79 * The lower four bits are reserved for future extensions.
80 *
81 * Scalar types (FS==0x00):
82 *----------------------------------------------------------------------
83 * These include the basic scalar types and 'standard' fixed size records
84 * used in fiff files.
85 *
86 * * It is required that the code is less than 0x0FFF (< 4096). !!!
87 * * Fourth byte is currently reserved for future extensions.
88 *
89 * Current types in this class are:
90 *
91 * FIFFT_VOID 0 Nothing
92 * FIFFT_BYTE 1 Unsigned? 8 bits
93 * FIFFT_SHORT 2 Signed 16 bit integer.
94 * FIFFT_INT 3 Signed 32 bit integer.
95 * FIFFT_FLOAT 4 Single precision IEEE float (32 bits)
96 * FIFFT_DOUBLE 5 Double precision IEEE float (64 bits)
97 * FIFFT_JULIAN 6 Julian day. (32 bits)
98 * FIFFT_USHORT 7 Unsigned short (16 bits)
99 * FIFFT_UINT 8 Unsigned int (32 bits)
100 * FIFFT_ULONG 9 Unsigned long (64 bits)
101 * FIFFT_STRING 10 Octet, ASCII coding.
102 * FIFFT_ASCII 10
103 * FIFFT_LONG 11 Long integer (64 bit)
104 * FIFFT_DAU_PACK13 13 13 bit packed format used in HP DAUs.
105 * FIFFT_DAU_PACK14 14 14 bit packed format used in HP DAUs
106 * FIFFT_DAU_PACK16 16 Signed 16 bit integer. (?)
107 * FIFFT_COMPLEX_FLOAT 20 Complex number encoded with floats
108 * FIFFT_COMPLEX_DOUBLE 21 Complex number encoded with doubles
109 * FIFFT_OLD_PACK 23 Neuromag proprietary 16 bit packing.
110 *
111 * Following are structure types defined in fiff_types.h
112 *
113 * FIFFT_CH_INFO_STRUCT 30 Basic info about a measurement chnnel.
114 * FIFFT_ID_STRUCT 31 Unique identifier.
115 * FIFFT_DIR_ENTRY_STRUCT 32 FIFF file directory entry.
116 * FIFFT_DIG_POINT_STRUCT 33 Digitization point.
117 * FIFFT_CH_POS_STRUCT 34 Channel position.
118 * FIFFT_COORD_TRANS_STRUCT 35 Coordinate transformation.
119 * FIFFT_DIG_STRING_STRUCT 36 Digitization string.
120 * FIFFT_STREAM_SEGMENT_STRUCT 37 Data stream segment.
121 * FIFFT_DATA_REF_STRUCT 38 Reference to external data.
122 *
123 * Simple vector of any scalar type can be formed by simply
124 * concatenating into file. The number of of elements is deduced
125 * from the size of the data block which should be a multiple of the
126 * object size.
127 *
128 * Futher more, for each scalar type fiff_types.h defines a corresponding
129 * C language type. Naming convention is fiff_xxx_t which correspons to
130 * type id FIFFT_xxx.
131 *
132 *
133 *
134 * Matrix types (FS=0x40)
135 *----------------------------------------------------------------------
136 *
137 * FIFF Matrix type is in principle an arbitrary dimensional rectangular
138 * collection of fixed size elements. However for practical reasons the
139 * maximum dimension is currenly restricted arbitrarily to 9
140 * (see FIFFC_MATRIX_MAX_DIM) but this restriction may be relaxed in the future.
141 *
142 * Matrix type codes use following structure:
143 *
144 * * Matrix type structure: 0xFFCCyyyy
145 * * Where
146 *
147 * 0xFF...... decribes the 'fundamental structure'.
148 * FF = 40 denotes a multidimensional matrix.
149 * 0x..XX.... describes to basic coding: dense, triangular, sparse etc.
150 * 0x....yyyy describes the element type.
151 *
152 * Current codings available are:
153 *
154 * FIFFTS_MC_DENSE 0x00000000 Dense column oriented matrix
155 * FIFFTS_MC_CCS 0x00100000 Column compressed sparse matrix
156 * FIFFTS_MC_RCS 0x00200000 Row compressed sparse matrix
157 *
158 *
159 * Dense matrix structure
160 * ----------------------
161 *
162 * A(1,1,...),A(2,1...) ... A(1,2,..) ... A(N,M,K...),K,M,N, ...,DIM
163 *
164 * where DIM is the dimensionality.
165 * N,M,K... are the dimensions.
166 * A(i,j,k...) are the elements.
167 *
168 * Note: the 2-dimensional meg_matrix format (routines in fiff_matrix.c)
169 * read and write the matrix in transposed form, i.e, the storing order
170 * in the FIFF-file is
171 * A(1,1),A(1,2) ... A(1,M) ... A(M,M),N,M,DIM
172 *
173 *
174 * Column compressed sparse matrix structure
175 *------------------------------------------
176 *
177 * A(x0,y0,z0...),A(x1,y0,z0),...
178 * ...,x0,x2...,x{NZ-1}, y0,y1,...,y{M-1}, z0,z1...,z{K-1},...,NZ,K,M,N,...,DIM
179 *
180 * where DIM is the dimensionality.
181 * N,M,K... are the dimensions.
182 * NZ is the number of non zero elements.
183 * A(i,j,k...) are the elements.
184 * x0..x(NZ-1) is row index array (concatenated for all vectors)
185 * y0..y(M-1) is column start index array for the second dimension.
186 * z1..z(K-1) is slice start index array for the third dimension.
187 * etc.
188 * Index arrays are 0 based.
189 *
190 * Row compressed sparse matrix structure
191 *---------------------------------------
192 *
193 * Similar to column compresses version except that dimensions 1 and 2 are
194 * interchanged. Structurally exactly same as ccs_matrix of the transpose.
195 *
196 */
