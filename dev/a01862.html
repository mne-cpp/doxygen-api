Detailed Description

Device control: the parameters, commands and status values a device publishes, and their events.

Every device describes what it lets a program set, run and watch while it is open, in one list of AcqControlInfo: parameters (a typed value, readable, optionally writable), commands (an operation with typed arguments and a result) and status values (read-only telemetry). A program reads, writes and invokes them by id through AcqDevice and learns about changes from AcqControlEvent records, which the backend publishes from any thread, the acquisition thread included, without locks or allocation. A change that alters how samples are scaled or named is also a new metadata version of the stream, valid from the sample it applies to (AcqStream::info(sample)), so data and their description never disagree.

The model is generic on purpose: an amplifier's range, a MEG system's SQUID tuning, a file simulator's file and an MR console's sequence are all parameters and commands of the same kind, so one user interface serves every device.

// What the device lets a program set, run and watch while it is open, and what it reports
for (const AcqControlInfo& control : device->controls()) {
const char* kind = control.kind == AcqControlKind::Command ? "command" : (control.kind == AcqControlKind::Status ? "status" : "setting");
std::printf(" %-7s %-13s %s\n", kind, control.id.c_str(), control.description.c_str());
}
std::array<AcqControlEvent, 32> controlEvents;
const auto reportAlerts = [&] {
for (std::size_t i = 0, n = device->pollControlEvents(controlEvents); i < n; ++i) {
if (controlEvents[i].kind == AcqControlEventKind::Alert) {
const std::string_view text = controlEvents[i].message();
std::printf(" device: %.*s\n", static_cast<int>(text.size()), text.data());
}
}
