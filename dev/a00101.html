mne::ConnectivitySettings carries the per-trial time-domain matrices, the derived per-trial cross-spectral data (DPSS tapered FFTs, CSDs and the imaginary-part variants needed by PLI / wPLI / dwPLI), and the accumulated cross-trial sums used to normalise the final estimates. Holding all of this in one object lets the dispatcher in mne::compute_connectivity compute several metrics in one pass without re-tapering and re-FFT'ing the same trials: the mne::ConnectivitySettings::IntermediateTrialData fields are filled lazily by the first metric that needs them and reused by everyone else.

The container also stores the spectral-domain parameters (sampling rate, FFT length, taper window name) and the 3D node positions used to lay out the resulting mne::Network - the latter can be sourced either from a FiffInfo channel set (sensor space) or from a forward solution and FsSurfaceSet pair (source space).
