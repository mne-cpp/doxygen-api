Detailed Description

AcqReader: one consumer of a stream with its own position, mode and exact loss count.

Input streams: any number of readers (recorder, display, closed-loop controller) consume the ring independently; the producer never waits for them. Output streams: the device backend consumes through one gating reader, which the writer waits for; further non-gating readers monitor what was sent (e.g. to record the delivered stimulus).

Cost model (throughput does not degrade with the number of readers): each reader's position lives on its own cache line and is written only by that reader; the producer publishes one position per commit and touches no per-reader state; a reader computes its loss from positions on acquire(); a blocked reader is woken by std::atomic::notify only when it announced that it waits. After start(), acquire() and release() perform no heap allocation and take no lock.

Zero-copy loop:

auto reader = stream.reader(mne::AcqReader::ReadMode::Lossless);
while (running) {
auto view = reader->lease(256, std::chrono::milliseconds(100));
if (!view) { if (view.error() == mne::AcqErrorCode::Timeout) continue; break; }
process(**view); // parts point into the ring
if (!view->release().ok()) discardLastResult(); // the producer overtook the view
}
